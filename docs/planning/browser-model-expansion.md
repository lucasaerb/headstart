# Expand browser games and expose creator-reported AI models

P0: user prioritizes a much broader browser/Three.js catalog, strongly biased toward games created with GPT-6 Astra or Fable 5/5.1.

Acceptance:
- Add at least20 distinct browser games or independently useful browser subprojects, with substantial Three.js coverage; label demos/toolkits separately from games.
- Verify actual repository/provider identity, pinned source paths, code-license evidence and demo destination; preserve unresolved rights and untested gameplay.
- Record model attribution as creator-attributed, unverified or unknown with exact model names, evidence URL, claim and limits. Curated-list membership, topic names or AI gameplay do not prove model-generated code.
- Show model labels and attribution evidence in the existing C4 dashboard, offer a model filter, and prioritize browser/Three.js and evidenced preferred models while preserving hard filters.
- Every newly displayed game must have an authentic image of that specific game, keyed to its exact catalog record and backed by image identity, credit, display-rights, provenance and digest evidence. A same-repository sibling image, generated substitute or generic project artwork does not satisfy this gate. Existing historical licensed previews may remain clearly labeled; records without cleared authentic images stay out of the displayed expansion rather than shipping placeholders.
- Popularity and an editorial “fun” recommendation remain separate signals. Calling a game interactive or curating it as especially fun requires a dated representative play observation with reviewer, environment, scenario and limitations; repository stars, an HTTP response, video, model attribution or source inspection alone is insufficient.
- Regenerate machine-readable and readable research exports with provenance. Old rows with no model evidence remain unknown.
- Builder/author produces data/code; separate reviewer checks primary sources, meaningful tests and actual desktop/mobile browse/filter/detail/bag interactions, fixes repeated until PASS.

No source export authorization, hosting change or public directory publication is implied. Code/model attribution is independent from license permission. Evidence and review go in docs/reviews/browser-model-expansion/.
