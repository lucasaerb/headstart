## Actual measurement and plan limits

Available tool: Node's monotonic `performance.now` timer. The executed workload is ten batches of 50,000 toy state-update calls after three warmup batches. Device/architecture, OS, exact Node version, settings and sampling method are retained in [raw.json](raw.json); [benchmark.json](benchmark.json) passes the existing canonical v0.2 BenchmarkRun validator and the packaged raw evidence checker. This is a single CPU-only local baseline. It has no rendered frames, uses an explicitly non-rendered 1×1 schema placeholder and cannot support gameplay FPS, GPU cost or a before/after speedup.

A real gameplay follow-up would pin the actual engine/browser/CPU/GPU, camera/input trace and seed, viewport/DPR and graphics settings; warm the same scene; capture a declared duration/sample count using an available profiler; retain frame-time distributions and raw traces; and repeat the identical profile at the expected before/after revisions. Background/thermal load, timer resolution and instrumentation overhead must remain visible. The user's budgets determine acceptable regressions; none were supplied here.

The local checker rejects absent/tampered raw bytes, unmeasured claim type, invented mean, empty/nonfinite/negative/bool samples, unsafe paths, stale source/target data and mismatched profiles. Passing that checker proves consistency with supplied bytes, not trustworthy measurement authorship. Independent review must examine the real command and raw results. The seven unit tests use explicitly synthetic values to exercise these rejection rules; only the separate Node fixture command produced the retained actual samples.
