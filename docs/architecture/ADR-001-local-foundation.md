# ADR 001: preserve the buildless C4 application

Accepted for local development, 2026-09-10, issue #2. The existing C4 site is plain HTML/CSS/JavaScript with a Vercel Node handler and pinned @vercel/blob 2.8.0. Keep that application, its art and identifiers intact. No framework migration is needed to establish reproducible engineering commands.

The inspected machine uses Node 22.22.3 and npm 10.9.8. `.nvmrc`, packageManager and the root npm lockfile select those versions; CI installs them explicitly. Root npm workspaces install the existing site dependency and exact Playwright/Prettier versions. Python contract work uses `requirements-dev.txt` separately. The Node server binds loopback only and serves an explicit public allowlist; it never exposes API source, package files, secrets or arbitrary workspace files.

`tools/dev/server.mjs` exports `createDevServer({apiRoutes})`. Extension handlers are exact path entries in `tools/dev/api-routes.mjs` and receive Node request/response plus Vercel-compatible `res.status().json()`. A bounded route resolver handles versioned detail paths. Handlers own validation, methods and authorization. `/api/subscribe` invokes the existing production handler; missing private Blob credentials produce 503. No local fake subscription success, email delivery, verification or cloud setup is implied. The combined #5/#6 metadata route requires local Python and initialized SQLite; it needs no external service.

`npm run build` assembles `.local-build/` through an explicit public allowlist, including the Gauntlet prompt module that the earlier Vercel build omitted and the #6 discovery module. The existing Vercel build allowlist now includes those modules too. Neither command deploys or bundles API handlers. Catalog persistence is implemented by #4, local API by #5 and the authoritative API UI by #6. Run the explicit catalog initialization command before browsing; no automatic seed runs on server startup. The static output alone cannot host this new API-driven experience without a separately reviewed production API adapter.

Checks cover JavaScript parse errors, new tooling formatting, server integration/private route protection, existing subscription tests and real desktop/mobile browser rendering/empty states. These are not gameplay, live Vercel delivery, verified identity or source integration tests. Existing C4 imagery remains the selected baseline; no replacement scaffold visual language was introduced.
