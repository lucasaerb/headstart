# HeadStart audience demo target

User direction recorded 10 September 2026. Status: desired demonstration, not implemented behavior. This request saves the target; it does not request producing a game or video now.

## The payoff

In a one-minute audience video, a developer discovers three appealing games, adds them to a grab-bag, and asks their Astra to mash up all three using actual source code. The audience then sees a coherent working game being played and an automatically recorded royalty entry for the original developers of the pieces actually reused.

Variety in genres and visual styles is welcome: the library should invite creative combinations. The demonstrated combination must still have defensible source choices, adaptation boundaries and validation. It does not establish that arbitrary games or engines can be combined automatically.

## Proposed 60-second sequence

| Time | Audience sees | Required substance |
| --- | --- | --- |
| 0–8 seconds | Browse three varied, appealing playable games. | Real game previews with verified source/demo relationships; the selection is understandable at a glance. |
| 8–17 seconds | Add all three to a visible grab-bag. | A persistent, editable selection records each game, selected source version and intended reuse scope. |
| 17–27 seconds | Ask Astra to combine the selected games into a clear game idea. | Their MCP tool/plugin automatically references the selected bag as agent context. No manual URL pasting or hand-assembled handoff is needed. |
| 27–40 seconds | A compressed view of the real adaptation/build process. | Show actual source reuse and checks; label any time compression. One minute describes video runtime, not build latency. |
| 40–53 seconds | Play the resulting game. | Demonstrate one coherent playable experience whose behavior uses pieces from all three sources; identify those contributions. |
| 53–60 seconds | See the creator royalty record. | Automatically record the original developers and the pieces actually reused, with provenance and applicable royalty terms or their unresolved status. |

The sequence is a planning proposal. No capture, integration run, working remix or royalty service is asserted here.

## Bag and agent contract

The bag is the bridge between browsing and the developer's existing agent. Its reference must resolve the selected bag revision, games, immutable source versions and scope. If a selection changes, the context must identify which revision Astra uses and refresh deliberately; it must not silently reuse stale choices. The user's latest explicit requirement is that their MCP tool/plugin references this context automatically.

Catalog and bag retrieval remain read-only. The agent separately inspects the selected target, resolves source/asset rights, plans the adaptation and performs authorized local work. Preserve target systems, source notices and enough evidence to connect copied or adapted files to their origin. Adding something to a bag does not prove it was used.

## Royalty record and evidence

Automatic royalty logging is part of the target, superseding its earlier deferral. Payment and settlement are separate and unspecified. Open-source visibility, a license or a dependency edge does not itself establish an economic agreement. Record applicable agreed terms when they exist; otherwise make unresolved terms explicit rather than inventing percentages, money owed or payment success. Ordinary attribution alone should not be presented as a completed royalty arrangement.

The eventual demonstration needs reviewed source/rights evidence, a traceable contribution from each selected game, a real playable result and a record that matches actual reuse. Current mockups and starter skills establish none of those outcomes.

## Next design pass

The three simplicity explorations predate this target. Preserve their alternate entry styles, then design the shared bag → remix brief → Astra → playable result → creator royalty record flow. Keep the bag and eventual playable payoff obvious; move technical detail into the decisions where it matters.
