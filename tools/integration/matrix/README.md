# Ten world capability integrations

This runner creates ten independently runnable authored existing-target fixtures, applies one reviewed capability into each target's explicit landmark slot in an isolated Git worktree, and executes unchanged/integrated browser scenes inside the issue16 bounded Docker sandbox. Target instructions authorize only the feature module plus scoped vendor/notices. The original renderer, camera, indexed flat world, keyboard explorer, frame scheduler and physics-none policy remain owned by the target.

The selected source matrix and replacement rationale are in `docs/reviews/reference-integrations/matrix-v1.md`. All upstream source is exact Three.js commit `5c5a575bd8cc0cf440026ce8dcf6a77862067684`, version0.186.0, including complete ConvexHull dependency closure and retained notices. Existing target engine bytes resolve the reviewed external peer without adding a second engine. No R3F, camera controller, browser pointer-lock, collision response or universal portability is claimed. Capsule uses its source-defined strict overlap query: exact tangency returns false. VertexTangentsHelper displays tangent xyz direction and world length; handedness w is not a bitangent or normal-map validation claim.

The target and integration are independently authorized local test work. The source review manifest supplies code scope/rights evidence. This runner neither bypasses nor pretends to exercise platform verified-email handoff. Target code is not uploaded, merged, published or automatically assigned a blanket license.

After the explicit engine fetch and immutable browser-image build described in the parent README:

```sh
.venv/bin/python -m tools.integration.matrix.run --row all --output /tmp/headstart-matrix --image <actual-immutable-image-id> --authorized
.venv/bin/python -m tools.integration.matrix.mutations --output /tmp/headstart-matrix-negative --image <same-image-id>
```

Use `--row` with any one of `simplexnoise`, `improvednoise`, `capsule`, `obb`, `roundedboxgeometry`, `parametricgeometry`, `boxlinegeometry`, `vertexnormalshelper`, `convexgeometry`, `vertextangentshelper` for independent reproduction. Each output path must be fresh. A run pins actual plugin version, source files/closure, instructions, base commit/file modes, integrated file modes/digests, recipe/harness, brief and environment. Changes invalidate the previous plan. Runtime results include desktop/mobile baseline and integration, capability oracles, preserved target behavior, resource/listener/frame cleanup and repeated mount/unmount. Negative runs reject a no-op and missing disposal for each row. These are runtime checks, not a claim that a build alone proves reuse.

Each successful run writes an exact `headstart-execution-0.1` attestation with actual phase log digests and matching scope/target/recipe. Its runner field marks author evidence. Validation remains **awaiting independent review**; creating files does not promote a catalog record. New immutable tested component/target/recipe records may be activated only after matching independent acceptance, with target permission separate from upstream MIT rights.

For bounded reversal, `tools.integration.matrix.run.rollback(job_path)` checks changed bytes/modes, restores the original feature and removes only its own vendor/notice files; unrelated worktree edits remain. The original target stays untouched. Matrix-specific unit tests complement issue16's authorization, target/source/recipe/right gaps, injection, interruption and rollback tests. No measured performance numbers are asserted.
