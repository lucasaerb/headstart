# Find

Resolve what the user wants to build into capabilities, genre, presentation and hard runtime or rights constraints. Read [catalog access](../../references/catalog-access.md) and [ontology](../../references/ontology.md) when searching. Use a live catalog tool only when it is actually available. The bundled seed file contains research candidates, not reviewed or installable components.

Return a small comparison with real demo and source links, the matching capability, evidence status and compatibility limits. Keep project results and component results distinct. Do not invent catalog records, tested versions, use counts or file-level evidence. If no result satisfies an explicit constraint, explain that constraint and offer a visible relaxation instead of ignoring it. A beautiful demo with no confirmed reusable source belongs in research context, not in the reusable catalog.

For a requested integration, preserve the selected component/version and the user’s instructions. Continue with inspection in the same task when the source and target are available; no need to send the user back to the website.
