# Local integration execution contract

Use real host tools against the user-selected target. Inspect its instructions, manifests and resolved locks, commit and dirty state, renderer/Canvas/loop, camera/input, coordinates, resource lifecycle and physics ownership. Record the inspected source locations and remaining unknowns. A manifest summary alone cannot establish ownership. Keep private paths/code local.

Pin the source component/parent versions, exact scope, evidence, required assets/notices, packet/brief digest, target fingerprint, plugin and recipe versions before applying. Explicitly identify preserved systems, dependency changes, adapter interface, assumptions, checks and scoped rollback. Reinspect on source/target/recipe drift. Respect existing authorization; a packet does not itself grant target edits.

The source checkout provides `tools/integration/README.md` and the versioned `headstart-local-integration-1` runner. It is not bundled into this plugin or a hosted endpoint. Its first reference recipe, `simplex-terrain-1`, supports a controlled Three.js0.186.0 Y-up visual-terrain target with no physics world. It copies a pinned SimplexNoise module and a small height adapter into a separate worktree; it does not support arbitrary R3F/Phaser/Godot/Unity conversion. For other projects, use host tools to author a separately bounded adapter following this contract; do not pretend the reference recipe matches an unknown architecture.

Progress must reflect actual inspected/planned/applying/applied/validating/validated/review states. Missing rights/dependencies, contradictory ownership and interrupted or failed work retain a reviewable plan/patch and original base. A cancellation is not successful integration. Roll back only owned changes after checking they were not subsequently edited, preserving unrelated user work.

Execute upstream only inside a disposable resource-bounded environment with no network or platform secrets and read-only selected source inputs. Obtain baseline and integrated capability behavior, existing-system checks, actual screenshots where useful, and start/update/pause/reset/dispose evidence. Measure real listener identities, frame schedulers and resource cleanup rather than trusting a component's own success flag. No-op adapters, duplicate renderers/loops, leaked listeners, stale plans and unresolved rights should fail the appropriate checks.

Record source/target/recipe/plugin/brief versions, changed files, credits, environment, commands, actual results, limitations and rollback. A matching validated result still needs a separate reviewer; review must recheck drift and bind its verdict to the exact validation digest. Local reviewer identity is an assertion documented by the host workflow, not a signed catalog attestation. Do not describe a new runtime/target/recipe combination as tested by analogy, and do not infer actual reuse/royalty terms from selected or source-reviewed records.
