# Technology companions

HeadStart's core download bundles first-party skills, references and the offline read-only catalog MCP. External starters and editor connectors are evaluated as optional companions; they are not copied or enabled merely because they are useful.

## Official Unity AI MCP

- Product: Unity Technologies' official Unity MCP Server, included with the `com.unity.ai.assistant` package. It is Unity product functionality, not code or an MIT-licensed dependency bundled by HeadStart.
- Requirements reported by Unity: Unity 6 (`6000.0`) or later, a project connected to Unity Cloud, an MCP-compatible client, and an active Unity AI trial or subscription. Unity AI and its MCP support are currently beta services whose availability and terms may change.
- Connection: Unity starts its editor bridge and installs a platform-specific relay under `~/.unity/relay/`. Supported clients can be configured from **Edit > Project Settings > AI > Unity MCP**. A manual client configuration launches the applicable relay binary with `--mcp`; HeadStart must not guess a platform-specific path.
- Security and effects: a direct external MCP client requires explicit approval in Unity before it can invoke tools; previously approved clients can reconnect automatically. Enabled tools can read project state and console output and can also create, modify or delete scene objects, edit C# scripts, change component values, and invoke editor actions. Treat connection approval and every requested mutation as access to the selected Unity project, not as read-only catalog browsing.
- HeadStart boundary: the portable HeadStart download does not contain Unity, the Assistant package, the relay, a Unity license/subscription, or a preconfigured Unity MCP server. Do not add a machine-specific relay entry to HeadStart's bundled `mcp.json`. Guide the user through Unity's own installation and approval flow only when they select a Unity project and request editor connectivity.
- Primary references: [Unity setup article](https://unity.com/blog/unity-ai-mcp-how-to-get-started), [Unity MCP overview](https://docs.unity3d.com/Packages/com.unity.ai.assistant@2.0/manual/unity-mcp-overview.html), and [Unity MCP setup](https://docs.unity3d.com/Packages/com.unity.ai.assistant@2.0/manual/unity-mcp-get-started.html).

## Official Unity agent-skills plugin

- Product: Unity Technologies' same agent-skills repository is available for Claude Code and Codex, with host-specific marketplace commands. At inspected commit `c3eea365477506c2cdd5403d2f48acd124bd5ed2`, its README reports version `0.1.0-beta` and says the repository's plugin payload ships skills only—no hooks and no MCP servers. Installing that payload does not itself install or replace the Unity MCP Server described above.
- Claude Code installation documented by Unity: inside a Claude Code session, run `/plugin marketplace add Unity-Technologies/unity-agent-plugin`, then `/plugin install unity@unity-agent-plugin`. These are in-session slash commands, not terminal commands. From a terminal, the pinned README separately documents `claude plugin marketplace add Unity-Technologies/unity-agent-plugin`, then `claude plugin install unity@unity-agent-plugin`.
- Codex installation documented by Unity: `codex plugin marketplace add Unity-Technologies/unity-agent-plugin`, then `codex plugin add unity@unity-agent-plugin`. This changes the user's Codex plugin configuration, so offer it only when the user requests the official Unity skills and let them review the marketplace source first.
- Rights and HeadStart boundary: the repository uses the Unity Companion License for Unity-dependent projects, not MIT. HeadStart links to Unity's marketplace flow and does not copy or vendor Unity's skills or branding into its archive.
- Evidence note: Unity's launch article for Claude Code describes a broader first-party offering that included engineering skills, Unity CLI and MCP. Preserve that claim as dated product context, but do not use it to contradict the inspected repository payload or infer that the current Codex skills plugin contains MCP. The official host-specific setup pages and inspected artifact define what each installation step actually supplies.
- Primary references: [Unity agent-plugin launch article](https://unity.com/blog/unity-plugin-for-claude-code), [Unity Claude Code instructions](https://docs.unity.com/en-us/ai/unity-plugin/claude-code), [Unity Codex instructions](https://docs.unity.com/en-us/ai/unity-plugin/codex), [pinned source](https://github.com/Unity-Technologies/unity-agent-plugin/tree/c3eea365477506c2cdd5403d2f48acd124bd5ed2), [pinned README](https://github.com/Unity-Technologies/unity-agent-plugin/blob/c3eea365477506c2cdd5403d2f48acd124bd5ed2/README.md), and [pinned license](https://github.com/Unity-Technologies/unity-agent-plugin/blob/c3eea365477506c2cdd5403d2f48acd124bd5ed2/LICENSE.md).

## Community Blender MCP

- Candidate: `ahujasid/blender-mcp`, inspected commit `5f8ddaf6e987c4aa0c3467fcc548838b28f64477`. No tags were returned during the inspection, so the commit—not the moving package name—is the evidence reference. The repository says it is third-party and is not made by or affiliated with Blender or the Blender Foundation.
- Rights: the repository root code license is MIT. HeadStart does not vendor the code or addon; external models, generated assets and third-party asset services retain their own terms and rights.
- Setup reported by the pinned README: register with Codex using `codex mcp add blender -- uvx blender-mcp`, install the Blender addon using `uvx blender-mcp install-addon`, enable **Interface: MCP for Blender**, then explicitly start its server from Blender. These commands download/execute a moving Python package, change Codex configuration and install code into Blender; never run them merely because the HeadStart skill loaded. Review the current package/version and terms with the user first.
- Execution boundary: the connector can create, modify and delete objects and run arbitrary Python inside Blender. Its safe mode defaults off. Prefer `BLENDER_MCP_SAFE_MODE=1`, retain version-control or duplicate-file rollback, restrict work to the selected `.blend`/asset scope, and still review generated scripts because safe mode is a mitigation rather than a sandbox guarantee.
- Privacy boundary: the pinned terms say telemetry consent is enabled by default and can collect prompts, generated code, scene metadata, viewport screenshots and manual-edit trajectory for training, research or datasets. Require the user to review and deliberately choose the addon telemetry setting before connecting private work. The terms also report that opting out still sends minimal anonymous usage (install/session IDs, tool/result/timing/version/OS/timestamp), even though richer content is excluded.
- External services: Poly Haven, Sketchfab, Poly Pizza, Hyper3D Rodin and Hunyuan3D integrations may involve network requests, separate terms and API credentials. Do not enable them, transmit private scene data, or reuse fetched/generated assets without the user's request plus applicable rights and credential handling.
- Primary references: [pinned source](https://github.com/ahujasid/blender-mcp/tree/5f8ddaf6e987c4aa0c3467fcc548838b28f64477), [pinned README](https://github.com/ahujasid/blender-mcp/blob/5f8ddaf6e987c4aa0c3467fcc548838b28f64477/README.md), [pinned MIT license](https://github.com/ahujasid/blender-mcp/blob/5f8ddaf6e987c4aa0c3467fcc548838b28f64477/LICENSE), and [pinned terms/privacy](https://github.com/ahujasid/blender-mcp/blob/5f8ddaf6e987c4aa0c3467fcc548838b28f64477/TERMS_AND_CONDITIONS.md).

## Release rule

Before promoting any third-party companion into the portable download, pin its version, establish code and asset rights for the exact packaged scope, document its permissions and execution boundary, and test installation plus rollback in a supported client. For vendor products such as Unity AI, follow the vendor's installation, account, entitlement and connection-approval flow rather than treating the service as redistributable open-source code. Neither path proves target compatibility.
